## Review and verification rule

- Read-only investigations are reviewed, but do not receive an end-to-end runtime gate because they
  change no product behavior.
- Every accepted code milestone is independently reviewed. Review findings are fixed and rerun
  before acceptance.
- Each code milestone has focused tests plus the real boundary it changes: PostgreSQL concurrency,
  S3 byte readback, process death/restart, migration, API, or payload parity as applicable.
- The full source-to-UI end-to-end gate runs only after resource fetch, candidate derivation,
  release publication, EDINET ingestion, and the owner-approved freshness/outage policy exist.
